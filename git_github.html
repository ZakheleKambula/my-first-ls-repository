Basic Command Line Commands (Launch School July 29, 2026)

Creating commands:

      mkdir - makes a new directory/folder
      mkdir ~/(name of directory here) creates a directory in the home folder. To move more than one file at once = mv *(means all) path (e.g., ~/my_notes)
      touch - create a file

Display Commands:

      cat (concatenate)- displays contents of a file
      less - displays displays contents of a file interactively
      ls - lists the items (files and directories) in the current directory
      ls -a(all) means display all including hidden files (the command must be followed by an argument)
      ls -lah displays all content including user profile permissions
      head - display the first part of a file
      tail - display the last part of a file
      more - display all contents of a file with scroll down option
      man (manual) - display documentation about a command (e.g., man tar)
      --help - displays help about the command married to the it, the argument(--help). For example, ls --help displays information about the command ls.
      which (argument) - displays the default executable path of the argument

Exit Commands:

      q - allows you to exit the operation of the commands less, more, and man.
      exit or quit - terminates the session and closes the terminal

Copy Commands:

      cp [source] {single pattern} [direction] - copies directory or file (keeps the reference/original with the newly created value/copy in the designated destination)

Navigation Commands:

      cd - change directory
      cd../ - go up one directory
      pwd (present working directory) - takes you back to working directory
      mv [source] {single pattern} [direction] - move or rename a directory or file
      ~ - changes to home directory
      / - changes to the root directory. Root is where everything resides (it is the highest directory) and home is user account resides
      . - current directory
      .. or ../ go up one directory(to the parent dir)
      ../.. - go up two directories, that is, one directory up from the next directory(.. or ../)
      / or ./ - home directory
      * (splat/asterisk) - followed by an arguement print out files with the same pattern. For example, *ing will print all files or directories ending with "ing."
      ls .. - displays contents of a parent's parent directory

Delete and Remove Commands:

      rm [source]- permanently removes files
      rm -r(recursive) [source] - permanently removes directories/folders and all its files

Print Commands:

      echo - repeats back what follows after it, for example, echo 'hello world' will return 'hello world'

Multi Purpose Commands:

      tar - archives, compresses, and extracts files

Randoms:

      flags - are additional commands-turned arguments that add an extra layer to the command. For example, ls -a, the flag (-a) makes the out to display everything in that file or directory including hidden files
      " " - if a directory or files is not a snake (i.e., words connected by underscores, e.g., launch_school) putting them inside quotation marks lets the computer threat the dir or file name as a single string. Failure to do this results in errors like "to many arguements," "no such directory or file."
      control + x - exits a terminal space that is not responding to commands and returns / (home)

Git and Github Basics:

      Git and Github are Software Control Management tools that "Keep a historical record of the files in your codebase. The difference between the two version control tool is that git runs locally (controls versions of your code base in your computer), while github runs remotely, keeps track of cloud-based versions of one's codebase allowing remote sharing and collaboration."
    Git Focus:
      git inti(means create a new repo in the current directory) - turns a directory into a git repo by adding .git at the end of the directory. This now allows the issuing of git commands in this newly "created" git repo. What is the difference between a dir and git repo? A dir is a folder in the computer and a git repo is also a folder but its specifically tracked by git to "keep a historical record of the files in a codebase. IMPORTANT - Do not initialize a git repository within another Git rep, for example, you have ~/zee/projects and you want to intialize another repo called "ptojects2026," do not ~/zee/projects/projects2026. Instead, you should intialize a new repo in the home dir, that is, ~/zee/projects2026. Also, remember to intialize the repo (command: git init) to convert it into a .git repo so Git tracks and keeps a historical record of the files in your codebase. However, if you accidently have, just delete the .git repo within that directory.
      git config --global init.defaultbranch main - sts up Git repos to use main repo
      git add (filename/s here) - stages files up to be committed (made into a bundle of changes)
      git commit -m (the flag tells git to attach the string message) "name of files here wrapped in quotation marks."

    Common Git Commands:

        git init - intializes a dir into a Git repo
        git config - allows you to config settings
        The three kinds of config application settings and how to use them:
            •git config --global (this is a flag that specifies location/destination) user.name "namehere" - commands Git to config user.name (namehere) in the ~/.gitconfig (--global) repo (personal).
            •git config --system (this is a flag that specifies location/destination) user.name "namehere" - commands Git to config user.name in the ~/etc/gitconfig making it applicable to all users of that system. Meaning all user of that particular local machine will share the same user name.
            •git config user.name "namehere" - will apply the setting to the current repo because there is no flag specifies location/destination.
            •git config --list - displays the current repo user details
        .gitignore - tells Git to ignore the files or directories in the repo with this command. If we want to apply this all files or dir with a specific extention, for example, .SQLlite:
            First, make sure you are in the .gitignore repo. This can be done either by the Explore (presing the specific repo namea) or terminal (nano) path routes and input your text in the prompt
            Second, ONLY when using the terminal option, specify the path, add the wild card (*), and the extension (e.g., .private). Something like so:
            ~/hiddenfiles/*.private - Git will ignore all files with the .private extension within the .hiddenfiles dir.

        Git Workflow Commands:

            git add "file names here" - stages the files to commit. NOTE: The present working dir should have a file/s inside or it will return "nothing to commit" error message.
            git commit -m (this flag allows you attach descriptive message stating the reasons for change and commit) "decriptive message of the changes wrapped in quotations - tells Git to commit the message.
            git --status - checks the status of the repo and lists the files to commit. REMEMBER, the pwd must be a git repo."
            git log - displays the commit histoty log
            git restore --staged (filename) - unstages files
            git rm --cached (filenamehere) - deletes the file but keeps and stages the deletion process to be passed to the commit command
            git restore (filenamehere) - restores the file to the version prior to be staged
